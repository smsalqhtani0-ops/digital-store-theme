# فتح التابلت ببصمة الجوال

تطبيق أندرويد واحد (Kotlin + Jetpack Compose) يعمل بوضعين: **وضع التابلت** و**وضع الجوال**.

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 1 | ربط Shizuku، حفظ الرمز مشفّراً، زر "اختبار الفتح" | ✅ هذه النسخة |
| 2 | الاقتران عبر QR والاتصال على الشبكة المحلية (NSD) | ⏳ |
| 3 | طلب الفتح، البصمة، التوقيع ECDSA والتحقق منه | ⏳ |
| 4 | Foreground Service ومعالجة الأعطال | ⏳ |

## بنية المرحلة 1

```
app/src/main/
├── aidl/com/tabletunlock/IShellService.aidl   واجهة خدمة shell
└── java/com/tabletunlock/
    ├── MainActivity.kt          اختيار الوضع عند أول تشغيل
    ├── TabletViewModel.kt       منطق شاشة التابلت وتسلسل الاختبار
    ├── data/AppPrefs.kt         الوضع المختار وطريقة إظهار لوحة الرمز
    ├── security/PinStore.kt     AES-256-GCM بمفتاح في Android Keystore
    ├── shizuku/ShellService.kt  يعمل بصلاحية shell، ويقبل input و wm فقط
    ├── shizuku/ShizukuManager.kt  الإذن، والربط، وتنفيذ الأوامر
    ├── unlock/UnlockController.kt  224 ← swipe ← text ← 66
    └── ui/                      الشاشات (RTL مفروض)
```

ملاحظات أمنية:
- الرمز لا يُكتب في أي log. سجل الاختبار على الشاشة يعرض أسماء الخطوات فقط.
- الأوامر تُنفَّذ بـ `ProcessBuilder` مباشرة، بدون `sh -c`، والخدمة ترفض أي برنامج غير `/system/bin/input` و `/system/bin/wm`.
- `FLAG_SECURE` يمنع لقطات الشاشة، و `allowBackup=false` يمنع النسخ الاحتياطي.
- حدّ لا يمكن تجنّبه: `input text <PIN>` يمرّر الرمز كوسيط لعملية `input` لجزء من الثانية،
  فيمكن لعملية بصلاحية shell أو root أن تراه أثناء التنفيذ. التطبيقات العادية لا تستطيع رؤيته.

## البناء والتثبيت عبر Android Studio

### 1) فتح المشروع
1. ثبّت Android Studio (إصدار Ladybug أو أحدث).
2. **File ← Open** ثم اختر مجلد `TabletUnlock` نفسه، وليس جذر المستودع.
3. انتظر انتهاء Gradle Sync. سينزّل Gradle 8.11.1 والمكتبات تلقائياً.
   إذا طلب SDK 35 فاقبل التثبيت من SDK Manager.
   إذا اقترح ترقية AGP أو Kotlin فيمكنك تأجيلها الآن.

### 2) تجهيز التابلت (أونر / MagicOS)
1. **الإعدادات ← حول الجهاز** ← اضغط على "رقم الإصدار" 7 مرات لتفعيل خيارات المطوّر.
2. **الإعدادات ← النظام ← خيارات المطوّر** ← فعّل:
   - **تصحيح USB**.
   - **تصحيح USB (إعدادات الأمان)** إن وُجد. بدونه قد يرفض النظام حقن اللمس.
   - **التصحيح اللاسلكي** (يحتاجه Shizuku بدون root).
3. **الإعدادات ← الأمان/كلمة مرور الشاشة**: اجعل القفل **رمز PIN رقمياً**،
   وفعّل **القفل فوراً عند الضغط على زر التشغيل** إن كان الخيار موجوداً.
4. ثبّت **Shizuku** من Google Play أو من GitHub (RikkaApps/Shizuku)، ثم افتحه
   ← **البدء عبر التصحيح اللاسلكي** ← اتبع خطوات الاقتران (رمز الاقتران يظهر في إشعار).
   ⚠️ بدون root يتوقف Shizuku بعد كل إعادة تشغيل، فيجب تشغيله من جديد بنفس الطريقة.
5. في MagicOS: **الإعدادات ← البطارية ← تشغيل التطبيقات** ← اجعل Shizuku "إدارة يدوية"
   وفعّل الخيارات الثلاثة، حتى لا يوقفه النظام.

### 3) التثبيت على التابلت
1. وصّل التابلت بالكمبيوتر بكيبل USB، ووافق على نافذة "السماح بتصحيح USB".
2. في Android Studio اختر الجهاز من قائمة الأجهزة في الأعلى، ثم اضغط ▶ **Run 'app'**.
   (أو من Terminal: `./gradlew installDebug`، وفي Windows: `gradlew.bat installDebug`)
3. يمكن التثبيت لاسلكياً أيضاً: **Device Manager ← Pair Devices Using Wi-Fi**.

### 4) تجربة المرحلة 1
1. افتح التطبيق ← **وضع التابلت**.
2. قسم Shizuku ← **منح الإذن** ← وافق. يجب أن تظهر حالة "متصل ✓".
3. أدخل رمز التابلت ← **حفظ**.
4. اضغط **اختبار الفتح** ولا تلمس الجهاز:
   ستنطفئ الشاشة، وبعد 5 ثوانٍ تشتغل ويُسحب للأعلى ويُكتب الرمز ← يجب أن ينفتح القفل.
5. ارجع للتطبيق واقرأ السجل في أسفل الشاشة:
   - **✅ نجح الفتح** ← الفكرة تعمل، وننتقل للمرحلة 2.
   - **ما زال مقفلاً** ← غيّر "طريقة إظهار لوحة الرمز" إلى `wm dismiss-keyguard` وأعد الاختبار.
   - **الجهاز غير مقفل بعد** ← فعّل القفل الفوري بزر التشغيل (الخطوة 2.3).
   - **فشلت خطوة …: SecurityException / INJECT_EVENTS** ← فعّل "تصحيح USB (إعدادات الأمان)".

أرسل لي نص السجل كما هو إن لم ينجح الاختبار. السجل لا يحتوي الرمز.

### الجوال (في المرحلة 1)
ثبّت التطبيق بنفس الطريقة واختر **وضع الجوال**. ستظهر شاشة مؤقتة فقط،
وتكتمل وظائفها في المرحلتين 2 و 3. الجوال لا يحتاج Shizuku.

## لتطوير الكود
- عند تعديل `ShellService.kt` ارفع `versionCode` في `app/build.gradle.kts`،
  أو أوقف التطبيق قسرياً، حتى يُعيد Shizuku تشغيل الخدمة بالكود الجديد.
- لتغيير الوضع لاحقاً استخدم زر **تغيير الوضع** في الشريط العلوي.
